# WP-20B: security report and drift integration

Implemented on `wp-20b-security-report`, 2026-11-05.

`report --sections security` opts into the existing security posture reader. It
can also be combined with other section names. A default report never invokes
that reader. The saved section uses the existing report schema, with columns
Check, Severity, Status, Subject, Detail and Advice. An empty check has a null
subject/detail row so its successful zero remains distinguishable from missing
evidence. Partial findings remain visible with their check status; unavailable
views and bounded-evidence notes appear in the section note. Advice comes from
the security reader. No SQL was added.

The default JSON and Markdown snapshot fixture was generated by executing
`src/report/index.ts` from master `7fbef024ec7369eba86d9a466467732f6049fa1e`
with deterministic query results and a normalized timestamp. The regression test
compares serialized JSON and Markdown byte for byte against that fixture.

History adds high, medium, low and info finding-count series when a security
snapshot exists. Missing snapshots, incompatible columns and unavailable evidence
produce gaps. These are counts of the security reader's findings, including
informational audit/parameter observations; they are not counts of vulnerable
accounts or a compliance score. An increase follows the existing count-series
worsening convention. Old histories without security retain their previous series.

`drift --scope security` reads only the powerful-privileges and public-grants
checks, once per target. It compares distinct subject/detail pairs (including
nested-role paths), their counts and distinct subject counts. Per-target totals
appear in notes even when equal. Subjects include users, custom roles and PUBLIC
as returned by the security reader. Missing views, truncation or incomplete role
expansion withhold the affected comparison. Existing drift exit codes apply:
3 for observed drift, 1 for an incomplete comparison without observed drift, 0 for
a complete match. The 19c refusal propagates. Both consumers audit SQL hashes,
row counts and sanitized failures without bind values or driver text.
