# WP-28C: fixed feature SQL PDB audit

Oracle 19c semantics; live PDB behavior is unverified (no approved live PDB).
All feature queries use the connected PDB service. DBA/ALL views describe that
container; ALL visibility is additionally limited by object grants. No CDB_ views
or cross-container queries are introduced. V$SESSION and V$SQL visibility is scoped
by the connected container; do not add CON_ID=0 (that would discard PDB rows).
Container isolation is supplied by Oracle, not by a guessed container name predicate.
Root refusal and identity collection belong to WP-28A.

References: [19c multitenant views](https://docs.oracle.com/en/database/oracle/oracle-database/19/multi/viewing-information-about-cdbs-and-pdbs-with-sql-plus.html),
[19c Reference](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/index.html),
[ADR alert visibility](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/V-DIAG_ALERT_EXT.html),
[undo](https://docs.oracle.com/en/database/oracle/oracle-database/19/admin/managing-undo.html),
[recovery area](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/V-RECOVERY_FILE_DEST.html).

PDB space undo/redo/recovery sections are deliberately unavailable: undo mode is
not inferred, and redo/FRA configuration is CDB-wide. No absence or sizing finding
is inferred from empty PDB rows. Tablespace and temp notes explain file visibility.
Reports label CDB-wide backup/redo metadata and retain unavailable section notes.
Sessions label visibility and instance startup; security labels common/inherited
grants and CDB administration scope; alert output labels container ADR visibility.
Missing grants (00942/01031) remain per-view unavailable evidence, with existing
fallbacks. Report fallback also accepts 01031. ORA-65040 degrades instead of aborting
fixed feature readers. Tools still throw errors under the PI convention; no agent
prompt, tool description, or successful ask result changes.

The inventory below identifies fixed query construction sites, including dynamic
SQL templates and human-readable verification SQL (never run). Queries reused by
report, drift and triage adapters retain the underlying reader semantics. SQL
fragments on the same line are listed together. No SQL text is taken from a DB.
